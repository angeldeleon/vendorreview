## [Unreleased]

A pass over the tri-state and the boundary around documents the vendor supplies, before any of this is published. Several of the items below broke a claim made in README.md or SECURITY.md, and that is its own defect: a security document describing a defence the code does not implement is worse than one that says nothing.

### Fixed

- **A zero-width character can no longer split a credential past redaction.** The invisible-character class covered the zero-width space and the bidi controls and nothing else, so a variation selector, a Unicode tag character, a Mongolian vowel separator, a combining grapheme joiner or a Hangul filler placed inside an access key defeated every redaction pattern. The value reached the API payload and the JSON report and rendered to a human as the intact key — the same defeat the sanitise-then-redact ordering exists to prevent, reached through a character nobody had listed. Every zero-width character is now stripped; separators that leave a gap the reader can see deliberately are not.
- **The credential pattern for a URL with userinfo is linear again.** There were as many places to put the user/password colon as there were colons in the run, and the tail rescanned to the end of it for each. `a://` followed by 64 KB of colons — one line of a text file, free to write — cost eight seconds of CPU inside `check`, the local no-network command, and an 8 MB document of such lines cost a quarter of an hour. The user half of userinfo cannot contain a colon, so excluding it makes that run deterministic and the pattern one forward scan. The timing test used `"a://"` repeated, which gives every scheme its own slash to stop at and never reached the case; it now uses the shape that broke.
- **A note quoting a vendor's document is escaped.** Review notes were printed whole as tool-authored prose, and one of them is not: the note saying a document could not be read carries the reason, and for a questionnaire response file that reason was the YAML parser quoting the vendor's own line back. A response file beginning `![](https://evil.example/px.png): [` put an image in a review that gets forwarded to that same vendor and pasted into a ticket. A note now holds its own sentence and anything it quotes in separate fields, so escaping the quote does not print backslashes through the sentence around it — and a parse failure is reported by position rather than by reproducing the file.
- **`vendorreview rereview` escapes the vendor name.** The short report for an unchanged engagement was the one line of Markdown assembled outside `report.py`, and it escaped nothing — on the one path where there is no other output beside it to notice a live image or a clickable link.
- **An ISO 27001 certificate no longer attests that its own scope covers the service.** ATT-07 read "a scope statement exists", which is true of every certificate, as "the certified scope covers what you are buying". A certificate scoped to facilities management at a head office therefore satisfied the objective and disappeared into the attested count — the single classic miss in ISO diligence, produced by the tool that exists to catch it. The certificate cannot settle this and no longer tries; the vendor can, through a new `iso_scope_covers_service` response key, and the scope statement is still quoted for the reviewer to read it against.
- **A blank `stage` no longer attests that the review happened before commitment.** The parser applies "evaluating" as a display default and records the question as unanswered; GOV-02 read that default as an answer. Silence recorded as evidence is the same merge as an absence read out of silence, in the direction that flatters rather than accuses.
- **A truncated report is not a Type I.** Every other absence the SOC 2 parser records comes from something it found; this one came from not having found "Type II", and on a document cut at a size cap "not found" means "not read". A report whose introduction explains what a Type I is and whose own designation sits past the cut came out as answered-no on ATT-02 — a definitive failure against a vendor, manufactured by a byte limit. SECURITY.md claimed this could not happen.
- **"Except for" somewhere in ninety pages is not a qualified opinion.** It is how a qualification is worded and also how a scope sentence is worded, and it was tested before the explicit wording — so a report saying "this is an unqualified opinion" and, forty pages later, "all customers except for legacy tenants" was recorded as a qualified opinion. That fact reaches the JSON report and the model as something it may cite, and accusing a vendor of a qualified audit opinion is disproved by opening the report. Explicit wording decides it now; the loose phrasing counts only on a line discussing the opinion.
- **`--document` is read through the same reader as every other file.** It had no binary check, no line cap and no page cap: `--document report.pdf` decoded the compressed streams lossily and sent the result to the analysis API in full, while the README says in terms that this tool does not parse PDF. An unreadable attachment is now recorded and printed like any other rather than aborting a review that would otherwise have run.
- **List answers are bounded on the way in**, matching the cap the integration list already carried. Each of them is serialised whole into the API request and the JSON report, and an unrecognised entry is amplified into a sentence of its own on the way — so a quarter-megabyte `data_classes` answer, comfortably inside the intake file budget and free to write, produced twenty thousand vocabulary notes and a 2.5 MB request.
- **Blocking questions past the rendered cut are counted rather than dropped.** That section is the deliverable, and a blocking question left off it is one nobody asks while the decision still waits on the answer.
- **The HTML page prints the review notes.** It was the one format that left them off, so it was the one format that did not mention a document it had failed to read.
- **The rating explanation is printed.** It was computed for every gap and used nowhere, while its docstring said it appeared beside the rating. A reader who thinks an item is overblown can now name the input they disagree with rather than conclude the tool is noisy.
- **"No exceptions noted" is no longer read as exceptions noted.** The positive pattern matched the substring inside the negative statement, so every clean SOC 2 was reported as having testing exceptions — the exact inversion the function exists to get right, on the sentence that appears in every SOC 2 ever issued. A line stating the negative is now excluded from the positive scan rather than merely losing to it, and the cross-line case that motivated the ordering still works: a summary saying "no exceptions" and a test result saying "exceptions were noted" resolves to exceptions.
- **A carve-out is only read where the report discusses a subservice organisation.** "Carve-out" appears in glossaries and in the auditor's boilerplate description of the two methods, and any occurrence was being taken as the answer. Reporting a carve-out against a vendor who has none is a serious claim to make on a word in a definitions section.
- **An unevidenced objective can hold the decision again.** Materiality was being read from the severity *after* the not-evidenced cap had been applied, and the cap sits a band below the blocking threshold — so it was arithmetically impossible for an unknown to produce more-information-needed. The cap exists to stop unknowns being overstated in the report; it had quietly disabled the one mechanism that turns an unknown into a question somebody has to answer.
- **Materiality is not the engagement-adjusted rating either.** Reading that instead raised every MEDIUM objective to blocking for any vendor touching personal data, and a review that opens with twenty-four questions gets two of them answered.
- **URLs are defanged after the Markdown escape, not before.** The defang inserts square brackets and the escape then escaped them, so the reader got `https\[://\]evil.example` — backslashes on the page and no defang worth the name.
- **Bare URLs are defanged at all.** Escaping brackets does nothing to a bare URL: there is no bracket. Every Markdown renderer autolinks one, and a review is forwarded to the vendor's account team and pasted into tickets, so a link that arrived in text the vendor wrote went out clickable with a security team's letterhead on it.
- **A leading `#` in untrusted text no longer forges a heading**, alongside the leading `>` that was already handled.
- **`vendorreview check` prints the review notes.** They carry the list of documents that could not be read, and leaving them off meant the one command a security team runs first was the one that did not mention an unreadable SOC 2 — a review quietly built on less than the reader believed, which is the exact failure the tri-state exists to prevent.
- **INC-02 is rated MEDIUM.** Nothing this tool reads can settle whether a notification deadline is fast enough for your own regulatory clock; that is a judgement the reviewer makes against the answer INC-01 collects. Rated HIGH it was permanently blocking for every vendor touching personal data, with no answer that could ever clear it — a review that always says more-information-needed says nothing.
- **DAT-02 no longer derives an absent transfer mechanism from a yes/no.** `cross_border` says whether data leaves the region; nothing on the form or in any document this tool reads names the mechanism, so an unanswered field was being reported as an absent transfer mechanism against vendors operating under clauses nobody had asked about.

### Added

- CI invariants asserting that no framework identifier in the catalog is malformed, that the decision is never read from model output, that silence is never recorded as an absence, that severity is clamped in both directions, and that nothing credential-shaped reaches the API payload or any of the three report formats.
- A timing test over the redaction patterns, because every one of them runs across documents supplied by the party being assessed.
- `iso_scope_covers_service` in the vendor response template: the one thing an ISO 27001 certificate cannot tell you about itself, asked of the party who can answer it.
- The rating explanation now appears beside each objective in the report — the catalog rating, the engagement adjustment, and the unknown cap where it applied.

### Removed

- Two unused dataclasses in the evidence reader, and their exports. Unused machinery in a published security tool is a liability, because a reader assumes it is load-bearing.

## [0.1.0] — 2026-08-10

Initial release.

- Structured intake covering how the vendor will actually be used — data classes and subjects, integration shape, network position, criticality, contract state — with blank recorded as blank rather than defaulted.
- Deterministic extraction from a SOC 2 report, an ISO 27001 certificate, a penetration test summary and a completed questionnaire. No model decides whether a report says "Type II", whether a period has ended, or whether a subservice organisation is carved out.
- A tri-state running through every type: attested, answered no, not evidenced. Silence in a document is never read as a no; unknowns are capped in severity and printed as questions rather than as findings.
- Forty-one control objectives with computed applicability and named evidence sources, each mapped to NIST CSF 2.0, ISO 27001:2022 Annex A, SOC 2 TSC and CIS Controls v8.
- A computed decision — approve, approve with conditions, more information needed, or do not proceed — derived from the evidence state rather than from model output.
- `vendorreview check` runs the full objective evaluation and decision with no API key and no network call.
- Model-assisted findings for risks arising from how the facts combine, schema-forced and validated against facts that exist and catalog control ids, with blast radius and data class clamped in both directions.
- Renewal: the second review of a vendor reports only what changed, compared structurally rather than by wording.
- Two-audience output — decision, conditions and vendor questions for the requester; the evidence state and framework mapping for the reviewer. Markdown, JSON and HTML.
